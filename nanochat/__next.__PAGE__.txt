3:T483,nanochat is a minimal, single-GPU-node harness for training GPT-class language models and chatting with them. It targets researchers and hobbyists who want to pretrain, fine-tune, evaluate, and talk to an LLM without managing a complex distributed framework. The core problem it solves is accessibility: reproducing GPT-2-level capability that once cost ~$43,000 now takes ~$48 and two hours on 8×H100 GPUs. A single command-line flag—`--depth` (the number of transformer layers)—sets the model's complexity; every other hyperparameter (width, heads, learning rate, training horizon) is derived automatically to be compute-optimal. The system works as a pipeline of standalone scripts backed by a shared library. `base_train.py` pretrains a GPT model on streamed parquet data, `sft_train.py` fine-tunes it on chat conversations, `rl_train.py` runs reinforcement learning with GRPO on math problems, and `chat.py` launches an interactive REPL. Underneath, the `nanochat` library supplies the GPT architecture, a BPE tokenizer, an inference engine with KV-cache generation, checkpoint management, and benchmark tasks like MMLU and GSM8K for evaluation.4:T439,After training, you need to measure how good the model actually is on standardized tasks. CORE is a suite of evaluation metrics from the DCLM paper that covers multiple-choice questions, schema completion, and language modeling. Few-shot prompting means you prepend a handful of solved examples before the actual question so the model understands the expected format without any fine-tuning. For multiple-choice tasks, the evaluator computes the log-probability the model assigns to each candidate answer and picks the highest. Per-character normalization divides each answer's log-probability by its length so longer answers are not unfairly penalized. Schema tasks check whether the model can fill in a structured pattern correctly. Language modeling tasks simply measure how surprised the model is by held-out text (perplexity). When running on multiple GPUs, results from each rank are gathered and combined so every GPU's portion of the evaluation set contributes to the final score.
